The problem

Retail and enterprise venues need to drive content on fleets of Smart TVs — menu boards, promotions, live spotlights — and change it now, from a browser, without walking to each screen. Off-the-shelf signage was either a closed appliance or a heavy CMS that couldn't target Samsung's Tizen/SSSP hardware or push updates in real time.

The goal: a platform where an operator edits a screen in a web console and every TV reflects the change within seconds — reliable enough to run unattended for weeks, and cheap enough to scale across many venues.

Architecture — three surfaces + infrastructure

Four repositories, one contract. A control plane, an API, an on-device player and the cloud that runs them — the API is the single source of truth and the WebSocket hub that keeps every surface in sync.

signage-web

React control plane — a drag-friendly editor for screens, playlists and scheduling. Operators publish; the API broadcasts.

signage-api

NestJS service with a WebSocket gateway and Prisma over PostgreSQL. The single source of truth and the real-time hub.

signage-tv

On-device player for Samsung Tizen / SSSP. Subscribes over WebSockets, renders content and reports playback state.

signage-infra

Terraform modules provisioning the AWS footprint — ECS services, networking and the managed database.

Inside the product

Decisions & trade-offs

WebSockets over polling

Menu changes and live spotlights must land in seconds, so the API pushes over a WebSocket gateway instead of TVs polling REST. Players hold a persistent connection and reconcile against REST on reconnect — the trade-off is connection state to manage (heartbeats, back-off reconnect), which is worth it for latency and server load on large fleets.

One API as the source of truth

Web and TV are deliberately thin. All screen, media and schedule state lives behind the NestJS API with Prisma, so the browser editor and the on-device player can never disagree about what should be on screen — the API decides and broadcasts.

Tizen / SSSP as a first-class target

Building the player as a React app packaged for Samsung SSSP meant designing for constrained device memory and long uptimes rather than a desktop browser. Streaming media over WebSockets from the SSSP surface measurably improved live-video performance versus the legacy approach.

Infrastructure as code from day one

The whole footprint — ECS services, networking, database — is Terraform, so a new environment is a plan/apply rather than console clicking. That discipline paid off as the platform grew across venues.
