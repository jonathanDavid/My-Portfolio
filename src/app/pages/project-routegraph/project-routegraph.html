The problem

Routing questions are path questions — shortest, fastest, what's reachable, which corridor carries the load. In SQL they become recursive self-joins; in a graph database they're one line of Cypher. This project makes that argument demonstrable: a real national road network you can query, with the Cypher on screen for every answer.

Two repositories, one contract: routegraph-db owns the data and the Neo4j schema; routegraph-web explores it — and also runs entirely without it, so the deployed demo needs no backend at all.

Architecture — one graph, two engines

  • ETL with real sources. 56 DANE municipalities and 69 curated INVIAS corridors are enriched by OSRM: real driving km/min and the actual road polyline per edge (simplified to ≤80 points), so rendered routes wind through the cordilleras instead of cutting straight lines across the map. An idempotent seed loads Neo4j (MERGE + relationship sweep) with APOC for weighted Dijkstra.
  • Dual engines, pinned to agree. The deployed site runs a client-side Dijkstra over the exported graph JSON — key-less, no server. Enter bolt credentials and the SAME Cypher runs against a live Neo4j from the browser over bolt-in-WebSocket — no API layer. Tests pin both engines to identical answers.
  • The graph corrected itself. Splitting the long northern corridors at their real junctions (Aguachica, Bosconia) changed the Bogotá→Santa Marta answer from a 1,145 km detour to the true 971 km Ruta del Sol — finer nodes, better shortest paths, exactly as graph theory promises.

Inside the explorer

Decisions & trade-offs

Browser → Neo4j, no API server
The official JS driver speaks bolt over WebSocket directly from the page. Credentials are user-entered and live only in localStorage; the deployed site ships none. A NestJS layer was the original plan — it turned out to be pure overhead for this shape of app.
Curated edges over a full OSM import
Importing all of OpenStreetMap would bury the teaching point in millions of segments. 69 hand-curated intercity corridors keep every query result legible — and each edge still carries real OSRM metrics and geometry, so nothing is invented.
Demo engine mirrors the database
The client-side Dijkstra exists so GitHub Pages can serve a working demo key-less. Tests pin it to the exact corridors Neo4j returns — if they ever diverge, CI fails.
Roadless as a feature, not a gap
Four departmental capitals have no road to the rest of Colombia. Hiding them would misstate the country; including them with an explanation turns a blank spot into the map's most interesting fact.

What I'd change at scale

  • Graph Data Science library (GDS) for betweenness/community detection instead of APOC brute force.
  • Secondary-road tiers (departmental network) with a level-of-detail toggle.
  • A scheduled ETL run so OSRM metrics track road openings (e.g. new 4G concessions).
