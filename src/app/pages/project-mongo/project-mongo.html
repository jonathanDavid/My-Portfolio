The problem

Every team eventually argues about Mongoose vs the native driver — usually with adjectives. Benchmarks you find online compare different code doing different work, which makes the numbers marketing. The fix is structural: one contract (bulk insert, point read, indexed range query, atomic update, a $lookup aggregation, and a multi-document transaction), two implementations, and a fairness suite that runs every operation through both and asserts identical results — including the transaction rolling back all partial stock decrements. Only then is timing meaningful.

The verdict, measured

What the numbers said

The tax lives in the driver, not the database
Where the server does the work (the aggregation), Mongoose costs ~12%. Where the driver does the work (casting 1,000 documents on bulk insert), it costs ~54%. Reads, updates and transactions sit between at 1.3–1.5×.
Best-practice Mongoose only
.lean() on every read, insertMany, schema-declared indexes. The classic accidental tax — hydrating full documents with change tracking — is deliberately not measured as if it were mandatory. No straw men.
What Mongoose buys for its tax
Validation, casting and index declarations in one place. The native version trusts its caller — which is exactly how silent bad data happens. My call: native driver + a thin zod layer at the edges for hot paths; Mongoose for read-light CRUD teams.
Honest constraints, published with the numbers
Localhost Mongo (no network latency — real wires shrink the relative gap), single-node replica set, machine specs and driver versions travel inside results.json.

The site ships the recorded results; the API repo reruns them with one command.
