The dashboard, under real traffic

The decisions that matter

  • Hysteresis, not flapping: three consecutive failed probes eject a backend, two consecutive passes readmit it — one flaky health check never destabilizes the pool. Tested against a real flapping httptest server.
  • Mark, don't write: the proxy's ErrorHandler records the transport failure instead of answering, so the attempt loop can retry the next healthy backend — 502 goes out only when every attempt is spent. A genuine backend 5xx is an answer, never retried; a consumed POST body is never replayed.
  • Cheap where it's hot: backends carry their own atomic state (healthy / in-flight / served); latencies land in a fixed 512-slot ring and percentiles are computed only when the dashboard reads, once a second.
  • SSE over websockets: one-way metrics fan-out doesn't justify a dependency. The dashboard is a single embedded HTML file; the stream is text/event-stream from stdlib.
  • The demo is the proof: go run . demo starts three synthetic backends — one deliberately failing health checks every 20s — plus bursty traffic. You watch ejection, redistribution and recovery happen, live.

Honest scope

  • L7/HTTP only — TCP balancing, TLS termination and connection draining are out of scope by design.
  • least-conn counts in-flight requests at this proxy, not true backend load.
  • Next: Kubernetes manifests (Deployment + probes + HPA) — a balancer is the perfect K8s subject.
