The game

What "no engine" means here

  • The loop: input → update → collision → draw on a raw AWT Canvas — timing, double-buffering and frame pacing by hand.
  • Rendering & animation: a layer system (Capa), drawables, and a sprite Animacion framework — sprite sheets before I knew the term.
  • Pathfinding: the grid becomes a graph; enemies search it for a route to the player's node. My first graph algorithm in production — the ancestor of the Route Graph's Dijkstra explorer.
  • Data-driven levels: Niveles.txt defines every level as a header plus a sprite-code grid, documented in FormatoDeMapas.txt — edit the text file, get a new level, no recompile.

Why freeze it?

A time capsule beats a facelift
Rewriting student code erases the evidence of growth. The commits stay as written; only the README was rewritten to explain what's actually inside.
The value is the struggle
This is where I first hit the problems engines solve — game loops, sprite timing, grid collision, audio latency, "how does the enemy find me?" Every later project rhymes with something first attempted here.

Read it like a fossil record

NetBeans/Ant project; a prebuilt jar lives in dist/ — arrow keys, space drops the bomb.
