The problem

Vision-language models describe beautifully and count terribly; object detectors count precisely and understand nothing. Worse, both fail on large images: a detector resizes a 4000px photo to 640px and small objects — a knife, a distant person — simply vanish. This project is the working answer to both failures: the detector counts, the model narrates, and tiling keeps small things visible.

Architecture — three lessons, learned live

  • Tiled detection for large images. The full-resolution photo is sliced into overlapping 640px tiles; YOLO runs per tile; boxes shift back to global coordinates and merge. Small objects that die in a whole-image resize survive — the exact failure mode behind "YOLO can't find my knives".
  • IoU alone leaves phantoms. A tile edge that cuts a person yields a fragment box: low IoU against the full box (union is huge), so classic NMS keeps both. The first live run found 8 people in a 4-person photo. Merging on IOS (intersection-over-smaller) as well fixed it — regression-tested with that exact story.
  • Don't ask a 7B to repeat numbers. Even handed the counts as "verified facts", LLaVA answered "four people" one run and "two" the next. The fix is architectural, not prompt-craft: counts_sentence() states WHAT and HOW MANY deterministically from the scan, and the model is told to add only actions, attributes and mood. Counting answers are now identical across runs — by construction.

Real sessions

Decisions & trade-offs

Prose only, boxes opt-in
The product is a describer, not a detection dashboard. YOLO output stays internal; /annotate exists for whoever wants to audit the grounding layer.
Heuristic router, not an LLM router
"Describe" vs "count/find" separates cleanly on vocabulary — a regex answers in microseconds what a model call answers in seconds, and unknown phrasing safely defaults to the grounded path. Same graph shape as the game-dev copilot, cheaper hinge.
Full resolution for the detector, downscaled for the describer
Tiling gives YOLO every pixel; LLaVA gets a 1024px thumbnail — it reads gist, not detail, and the bandwidth/latency saving is free.
Same testability seam as its sibling
FakeVisionLLM and FakeDetector run the entire graph in under a second offline — 14 hermetic tests pin tile planning, both NMS merge modes, path routing, the grounding contract and the streaming callback. The pure tiling math is the most-tested file.

What I'd change at scale

  • Open-vocabulary detection (YOLO-World) beyond COCO's 80 classes; domain fine-tuning for targets like weapons.
  • An OCR node for text-in-image questions; batch captioning to JSON for alt-text pipelines.
  • A web UI with the annotated scan as a toggleable overlay.
