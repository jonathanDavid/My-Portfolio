The problem

Agent frameworks are easy to demo and hard to trust: a freeform loop calls tools until something plausible appears, and you can't see why — or test any of it without burning API credits. This project takes the opposite stance: an explicit LangGraph where every step is a named node, every answer prints the path it took, and the entire workflow runs under pytest in one second with no model at all.

And the subject is conversation, not configuration: tell it "I want you to be an expert in Svelte" and an agent searches the web (key-less), picks the site that looks like official documentation, crawls a bounded set of pages, and indexes them into that subject's own vector store — then your questions are answered from that corpus, with citations. Subjects persist as small JSON profiles you can also hand-curate; the shipped demo researches 12 game-dev frameworks. A hermetic test proves a custom subject leaves no trace of the demo domain in any prompt, and weak retrieval scores inject an explicit demand to admit the gap instead of summarizing the wrong docs.

Architecture — one graph, three routes

  • Router node: the first Mistral call does classification only — docs / video / chat, one word, defensively parsed with a keyword-heuristic fallback. It's the only place the LLM touches control flow, and even that is fenced.
  • RAG path: the question is embedded (nomic-embed-text) and Chroma returns the nearest chunks by cosine — real doc passages, chunked ~400 words with overlap at index time. The generate prompt orders the model to answer FROM them, cite [n], and admit gaps: the anti-hallucination contract.
  • Tool path: the model never executes anything — our code performs a key-less YouTube search (parsing ytInitialData) and feeds real results back into the prompt. A broken tool degrades to an honest "nothing found", never a crash.
  • Memory: a conversation buffer re-sends recent turns (models remember nothing), while durable project decisions — /remember my game uses arcade physics — persist to JSON and are injected into every prompt. That triage is context management.
  • The testability seam: every model call goes through two tiny protocols (LLM, Embedder). Production plugs in Ollama; tests plug in scripted fakes and a deterministic hash embedder — 20 hermetic tests assert paths, grounding, memory persistence, router salvage, web-docs discovery, and subject reskinning, offline.

Decisions & trade-offs

Local 7B over a cloud frontier model
60–90 s per grounded answer on CPU, and occasional imprecise paraphrasing — accepted, because the goals were privacy, zero cost, and honesty about what small local models can do. The citations make the imprecision checkable; a bigger model slots in by changing one string.
Explicit graph over a freeform agent loop
Nodes and conditional edges mean the flow is inspectable and every run is traceable (state.path). The cost is flexibility; the win is that tests can assert exactly which route a question takes.
Index only what servers actually send
Some doc sites are client-rendered SPAs (a fetcher receives an empty shell) or block non-browser agents. Those are skipped and noted in the corpus file rather than half-indexed — a small honesty lesson every RAG system eventually learns.
No hosted demo, on purpose
Local inference cannot run on GitHub Pages, and simulating an agent would undermine the project's whole argument. The repo is the demo: clone, run 20 tests in seconds, then pull the models and tell it what to become an expert in.

What I'd change at scale

  • Answer streaming for perceived latency; a golden-set retrieval eval in CI.
  • A web UI rendering the graph path visually, with a recorded-transcript demo mode.
  • A summarization node when the conversation buffer overflows, instead of drop-off.
