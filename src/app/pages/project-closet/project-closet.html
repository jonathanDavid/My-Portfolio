The problem

Seven years of mobile-platform drift in one repo: Expo SDK 30, React 16.3, react-navigation v2, native-base 2, rn-fetch-blob, Firebase v5 — every single dependency is dead. An in-place upgrade doesn't exist; v2 navigation APIs are gone, native-base is deprecated, the camera library is abandoned. The honest engineering call was a fresh Expo 57 + TypeScript app carrying the same product, with the 2019 implementation preserved in history — a revival, not a resurrection.

Before / after

Decisions & trade-offs

Local-first, not Firebase
The 2019 app needed an account before it showed anything. The revival keeps everything in AsyncStorage behind one reducer — no accounts, no keys, useful in seconds — and a cloud sync layer can plug into that same seam later.
Photos optional
The old flow forced the camera before a garment existed. Now a garment is a name + category + color swatch in ten seconds; a photo can come whenever.
Empty states as design, not absence
Every tab explains what belongs there and how to add it — the 2019 app rendered blank white lists.
Four tabs, one glance
Closet · Outfits · Laundry · Planner. The old app nested list → list → detail three levels deep before showing a garment.

What I'd change at scale

  • Cloud sync + auth behind the existing reducer seam — the 2019 Firebase idea, done properly.
  • On-device background removal for garment photos.
  • Wear statistics: cost-per-wear, seasonal rotation hints.
  • Reducer and planner date-math tests.

Open the closet

npm install, expo start — the seed closet shows every screen immediately.
